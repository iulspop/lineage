# Changelog

All notable changes to `@lineage/core` are documented here. Package API, durable corpus format, policy identities, and generated Agda runtime are versioned independently as described in the README.

## 0.0.0 — 2026-09-02

Initial private workspace package.

### Added

- Authoritative corpus validation and canonical serialization extracted from the web application.
- Packaged generated Agda runtime and compatibility adapter.
- Stable revision-bound reading segments and append-only generalized learning observations, with backward-compatible default-empty decoding.
- Deterministic evidence folds for recall, reading position, target summaries, recency, and diagnostics.
- Replaceable recall-policy contract with the existing FSRS-6 behavior and policy identity preserved.
- Candidate generation for due/new recall, authored practice, reading segments, and lessons with explicit eligibility rationales.
- Deterministic scoring, semantic interleaving, budget enforcement, deferred candidates, and plan rationales.
- Baseline prerequisite-readiness, incremental-reading, and mathematics-lesson policies over authored content.
- Cohesive `createLineageCore` facade.
- Core-owned proved Review transitions and recall-queue planning used by the Lineage web application.
- Conformance, parity, disclosure-safety, package-purity, determinism, and 100,000-Prompt/1,000,000-event scale verification.

### Compatibility

- Existing V1 corpus documents remain valid.
- Existing Repetition encoding and recall interoperability semantics are unchanged.
- npm publication is intentionally deferred.
